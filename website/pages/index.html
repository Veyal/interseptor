One static binary · v{{.Site.Release.Version}} · MIT

Finding the bug is the easy half.

Interseptor intercepts, replays and fuzzes the way you would expect. Then it refuses to call a report final until the evidence is attached. One Go binary, no JVM, no licence tier.

Proxy · History

Stage 1 of 5

Capture

Point a browser, a phone or a CLI at the proxy and every exchange lands in History. Metadata goes to SQLite and bodies stream to disk, so you can search headers, tags and bodies, or save a Starlark predicate for the next engagement.

Repeater

Stage 2 of 5

Replay

Send any captured request to Repeater, change it and send it again. Every tab keeps its own send history, and a response opens as raw, pretty, decoded or a sandboxed HTML render.

Repeater in the workspace guide
Intruder

Stage 3 of 5

Fuzz

Mark positions, load payloads and run Sniper, Pitchfork or Race with your own threads and delays. There is no throttle, because there is no tier to upsell. Anomalies are flagged, and a recorded run renders as a report-ready PNG.

Intruder in the workspace guide
Attach as evidence

Stage 4 of 5

Prove

Attach the captured flow to a finding, and each reproduction step carries the exchange that proves it. Only a real browser or device screenshot counts as visual proof: generated previews carry a marker, and the store refuses them as screenshots.

Findings · Report preflight

Stage 5 of 5

Report

Preflight names every blocker before you export. Ask for a final report with a gap still open and you get a 409 listing the failing checks, not a polished document with a hole in it. Out come Markdown, self-contained HTML or JSON.

Weak points

  • No active scanner. 31 passive checks over traffic you already captured, extensible in sandboxed Starlark. If you want an automated active scan, ZAP is free and good at it.
  • It is new. First commit June 2026. Burp's lineage goes back to 2003, ZAP's to 2010. It is MIT, so read the code: roughly 100k lines of source against 88k of tests.
  • No extension marketplace. Starlark checks and signed rule packs, and that is all. Burp has 300+ BApps from 250+ authors; that gap is real.
  • No hosted out-of-band service. There is a self-hosted catcher, off by default, and it needs your own tunnel to be reachable. It is not Burp Collaborator.
  • No HTTP/3. HTTP/2 upstream with an HTTP/1.1 client leg on the MITM path. mitmproxy does HTTP/3 today.
  • Data at rest is not encrypted. Captured traffic sits unencrypted under your data directory, by design. Secure the machine it runs on.

The architecture page also lists where the build deviates from its own spec, including a control left out of the UI because it could not be honest about what the server would do.

Does this replace Burp Professional?{{icon "plus" "lp-faq-icon"}}

Not its scanner, and not Collaborator. What it replaces is paying $499 a year for manual tooling you already know how to drive: unthrottled fuzzing, projects that persist, authorization differentials and reporting. Run it next to whatever you already use. Projects export as JSON or a full archive, so trying it is reversible.

Burp and ZAP have MCP too. Why does yours matter?{{icon "plus" "lp-faq-icon"}}

They do, and anyone saying otherwise is selling you something. There are three honest differences. Ours is in the binary rather than an extension you install and version-match. It is 133 first-party tools covering the workflow end to end, including findings and reporting. And create_finding makes the agent attach evidence before the finding counts. None of the tools on the comparison page has an equivalent of that last one.

Is my captured traffic going anywhere?{{icon "plus" "lp-faq-icon"}}

No analytics, no telemetry endpoints, no provider keys in the binary. The only host it contacts on its own is GitHub, to check whether a newer release exists, and you can turn that off. Everything else leaves only if you deliberately open a tunnel. Note that data at rest is unencrypted.

Can I use it headless, over SSH?{{icon "plus" "lp-faq-icon"}}

Yes. It is one binary with a loopback control API, and interseptor run drives a collection from CI and emits JUnit. The UI is served over HTTP, so forward a port and use a browser wherever you are.

Will it defeat certificate pinning?{{icon "plus" "lp-faq-icon"}}

No, and neither will any other proxy. It detects pinning and tells you which instrumentation path you need.
