    System proxy
    
            
    Route this machine's traffic through Interseptor (macOS only).
    
            
    
          
    
          
    
            
    Capture policy
    
            
    Store only in-scope traffic. Out-of-scope requests are still forwarded.
    
            
    
          
    
          
    
            
    Browser background traffic
    
            
    New traffic only; forwarding and existing History are unchanged.
    What is hidden?
    Known Firefox and Chromium telemetry, remote-settings, update, crash, Safe Browsing, suggestions, sponsored-content, and connectivity requests. Normal website and application traffic remains visible.
    
            
    
          
    
          
    
            
    Android telemetry
    
            
    App backends, auth, and FCM push stay visible.
    What is hidden?
    Play/GMS check-in, Crashlytics, Analytics, connectivity probes, and ad/measurement requests.
    
            
    
          
    
          
    
            
    Invisible proxy
    
            
    Accept traffic from clients that aren't proxy-configured (e.g. redirected via iptables/pf, DNS spoofing, or port forwarding). Origin-form requests are forwarded to their Host header. Off by default.
    
            
    
          
    
        
    
        
    
          
    TLS & certificates
    
          
    
            
    Origin connection security
    
            
    Choose whether Interseptor verifies the real server after decrypting client traffic. This setting affects origins only; HTTPS upstream proxies are always verified.
    
            
    
              
              
            
    
            
    Compatibility mode accepts self-signed, expired, and hostname-mismatched origin certificates so authorized test environments remain reachable.
    
          
    
          
    
            
    TLS certificate authority
    
            
    Install & trust this CA to intercept HTTPS. HTTP works without it.
    
            Download CA certificate
          
    
          
    
            
    TLS passthrough · SSL pinning
    
            
    Domains listed here are tunneled straight through without interception, so pinned apps keep working while you focus on the domains you can intercept. One host per line — exact (api.example.com) or wildcard (*.example.com).
    
            
    Adds a domain here automatically the first time its TLS handshake fails (pinning).
    
            
            
    
          
    
          
    
            
    Origin TLS verification exceptions
    
            
    Warning: matching origins stay intercepted, but Interseptor accepts any server certificate. This permits server impersonation. This is not TLS passthrough; captured traffic remains visible. One host per line — exact (api.example.com) or wildcard (*.example.com).
    
            
    IP certificate error? If History says the certificate “doesn't contain any IP SANs”, use the certificate's hostname when possible. For an authorized test target, add its IP here instead.

    Interseptor decrypts HTTPS only when the client trusts the CA. It does not bypass SSL pinning.

    Troubleshooting reference
              
      
                
    • TLS blocked — the app sent CONNECT but rejected the MITM cert (pinning or untrusted CA). Look for red PIN rows in History.
      • 
                
    • No traffic — nothing reached the proxy. Check proxy settings, adb reverse, or whether the app ignores the system proxy.
      • 
                
    • No HTTPS — only cleartext HTTP captured, or HTTPS never went through the proxy.
      • 
                
    • OK — HTTPS interception is working.
      • 
              
    
            
    
            
    Bypass pinning (on device)
              
      
                
    • Frida / objection — runtime hooks for OkHttp, custom TrustManagers, Flutter/Dart HTTP
      • 
                
    • Patched APK — repack with network_security_config or smali-patch pinning
      • 
                
    • Emulator + system CA — enough for apps that trust system CAs but don't pin
      • 
                
    • Root + Magisk / LSPosed — persistent bypass modules
      • 
              
    
            
    
          
    
          
    
            
    
              
    HOW TO TRUST IT
    
              
    macOS
      
                
    1. Open the downloaded interseptor-ca.crt — Keychain Access opens.
      2. 
                
    2. Add it to the System (or login) keychain.
      3. 
                
    3. Double-click the Interseptor CA → expand Trust → set When using this certificate to Always Trust.
      4. 
              
    
              
    Windows
      
                
    1. Double-click the .crt → Install Certificate.
      2. 
                
    2. Store location Current User → Place all certificates in the following store.
      3. 
                
    3. Choose Trusted Root Certification Authorities → Next → Finish.
      4. 
              
    
              
    Firefox (uses its own store)
      
                
    1. Settings → Privacy & Security → Certificates → View Certificates.
      2. 
                
    2. Authorities tab → Import → pick the .crt.
      3. 
                
    3. Check Trust this CA to identify websites → OK.
      4. 
              
    
              
    iOS
      
                
    1. Use the Mobile devices tab (iOS) — Setup all for Simulator, or download the profile for a physical iPhone.
      2. 
                
    2. Settings → General → VPN & Device Management → install the Interseptor profile.
      3. 
                
    3. Settings → General → About → Certificate Trust Settings → enable full trust for the Interseptor CA.
      4. 
              
    
              
    Android
      
                
    1. If adb is installed, use the Mobile devices tab (Android) for one-click proxy and CA install.
      2. 
                
    2. Manual: Settings → Security → Encryption & credentials → Install a certificate → CA certificate.
      3. 
                
    3. Note: user CAs are not trusted by most apps on Android 7+; testing app traffic may need a rooted device or a network-security-config.
      4. 
              
    
              
    Linux (system / CLI)
      
                
    1. Debian/Ubuntu: copy to /usr/local/share/ca-certificates/interseptor.crt → run sudo update-ca-certificates.
      2. 
                
    2. Fedora/RHEL: copy to /etc/pki/ca-trust/source/anchors/ → run sudo update-ca-trust.
      3. 
                
    3. curl/wget one-off: curl --cacert ~/.interseptor/ca/ca.crt -x http://127.0.0.1:8080 https://…. Many tools also honour SSL_CERT_FILE/REQUESTS_CA_BUNDLE pointing at the CA.
      4.

    Technical finding template
    Write for fast triage, independent reproduction, and retesting.
    
      
    
    
    
    Engagement close-out checklist ↗
    
      
    1
    Title
    Name the weakness, affected action, and asset. Prefer “Broken object authorization exposes invoice records” over “IDOR issue”.
    
      
    2
    Claim
    Summarize who can do what, to which asset, and under which missing or failed control in one sentence.
    
      
    3
    Impact
    State what an attacker gains, the required access, and the affected data or operation. Do not restate the payload.
    
      
    4
    Technical context
    List all affected targets and their roles. Record environment, CWE, and a CVSS v4.0 vector; severity must match the calculated score.
    
      
    5
    Reproduction
    Attach evidence for the triggering action, observed result, and a negative/control case. A reachable prerequisite alone does not demonstrate the claimed impact.
    
      
    6
    Evidence
    For visual claims, attach a real browser capture of the observed result. Classify its origin; generated previews do not qualify. Annotate each item and redact secrets; use a length or digest where sufficient.
    
      
    7
    Remediation and retest
    Recommend the failed control, then record the expected secure result so another tester can verify the fix.
    
      
    Ready-to-report checkReview highlights action, result, control, visual proof, CVSS, and target evidence separately. If impact was not demonstrated, record why and keep Needs verification. Never infer missing execution.
