# Embedded UI responsive actions

Use this when changing a generated action row, list/detail workspace, or narrow-window layout in
`internal/control/ui/`.

## Hidden means hidden

Component rules such as `.actions { display:flex }` override the browser's user-agent `[hidden]`
rule. Keep the author-level contract `[hidden]{display:none!important}` in `app.css`; do not depend on
the user-agent stylesheet for edit/read mode, settings sections, or modal state.

## Grid ownership

Every direct child of a CSS grid consumes a cell. A flow card plus a sibling action button in a
two-column numbered-step grid places the button in the next row's number column. Wrap content and its
actions in the step-body cell:

```html
<div class="step">
  <div class="step-number">2</div>
  <div class="step-body">
    <button class="evidence-card">…</button>
    <div class="evidence-actions">…</div>
  </div>
</div>
```

Give every nested flex/grid content owner `min-width:0`, wrap action rows, and explicitly contain
long URLs or raw-data text.

## Async navigation actions

An action that loads data into another panel must resolve and validate source data before switching
panels. Disable the initiating button and show a loading label. On failure, remain in context and
restore the button; on success, navigate only after destination state is complete.

## Browser checks

Exercise the real generated state, not only empty panels. At minimum inspect 1440, 1024, 720, and
390 CSS pixels. Assert document and workspace scroll widths, inspect bounding rectangles for action
controls, and click the action through to its populated destination. Capture before/after screenshots
for visually ambiguous grid defects.
